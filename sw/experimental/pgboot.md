# PGBOOT: boot floppy and hard disk images from the USB drive

Experimental feature, on top of PGDFS (`sw/pgdfs`). Available in all modes with PGDFS. The option ROM and its tools are in `bootrom/` (`PGBOOT.md` in a release), the wire protocol in `sw/bootdisk/PROTOCOL.md`.

- An option ROM (`PGBOOT.ROM`, in an EEPROM on a ROM card such as the Monotech DoubleROM, or loaded by `PGBOOT.COM`) can present a disk image file on the PicoGUS USB drive to the BIOS as floppy drive A: and/or hard disk C:, so the machine boots from it. The card serves the sectors over the PGDFS transport with new requests (`BDINFO`, `BDREAD`, `BDWRITE`, see `sw/bootdisk/PROTOCOL.md`), in every firmware mode that carries PGDFS.
- Raw images and fixed VHD files are supported. Floppy geometry comes from the image size (160K to 2.88M, DMF 1.68M/1.72M) or its DOS boot sector; hard disk geometry from the VHD footer, the partition table, the boot sector, or 16 heads / 63 sectors. Images are kept open with a FatFs fast seek map (a hard disk image too fragmented for it is refused with a message to copy it to a freshly formatted stick), and written sectors reach the USB drive before the write is acknowledged.
- Safety: after the card boots (mode switch, firmware update) it opens no image until the ROM asks at the next boot, and every sector request carries a token that identifies the card boot and the image file, so a running system is never handed a different disk: a swapped floppy is reported as a media change, a hard disk that changed as not ready. Replugging the same USB stick carries on where it was.
- `pgusinit /fdimage <path|->` selects the floppy image (swapped in at once, reported to DOS as a media change), `/hdimage <path|->` the hard disk image (used from the next boot), `/bdopts <0-15>` the options (read-only floppy / hard disk, ROM disabled, boot the hard disk image). They are saved with `/save` and shown in pgusinit's status output.
- While an image is in use, PGDFS refuses to delete, rename or write that file (access denied).
- Boot menu: at boot the ROM offers a menu (`pgusinit /bdmenu <0-2>`: off, offered for `/bdwait <1-15>` seconds with M, which is the default, or opened at every boot). Its main menu leads to the floppy images and the hard disk images on the USB drive (folders, then `.IMG` `.IMA` `.VFD` `.FLP` `.DSK` up to 2.88 MB as floppy images, larger ones and `.VHD` `.HDD` as hard disk images, long names shown; Enter puts one in A: or C:), the boot order when both drives hold an image, the start-up tunes, the card's modes (the card restarts in the one chosen), the colours, Save Settings and Boot. The menu's content comes from the card (`BDLIST` lists), so new firmware can add to it without a new ROM.
- Start-up tune: when the ROM has found the card it plays a tune on the PC speaker. The tunes are on the card: eight come with the firmware (four short jingles, three in the manner of GUS-era game music, the opening of the Doom theme), and one is your own, given as RTTTL text with `pgusinit /bdmelody <text|@file>`. `pgusinit /bdtune <off|1-8|custom>` selects, and so does Boot Melody in the boot menu, which plays the tune chosen. The ROM times the notes with the system timer's counter, so the tempo is the same on every machine.
- The boot menu looks like the web page of the web server feature, in its three sets of colours (Setup with double-line window frames): `pgusinit /bdtheme <setup|commander|mono>`, or Colours in the menu.
- `PGBT256.BIN` is the ROM for a 28C256 written in an EPROM programmer: the 8 KB image in every quarter of the chip, right for either size setting of a Monotech DoubleROM.
- The ROM's INT 13h AH=48h answer had the cylinder, head and sector counts in the high words of the following fields, which made FreeDOS take a small image for a drive beyond 8 GB.
- The settings version is 9 (PGDFS alone: 7; the mainline firmware: 6): settings saved by this firmware are reset to defaults when firmware without PGBOOT is flashed back.
- Tested in an emulator only (`tools/emu`: QEMU with a bridge to the card's real server code, 25 end-to-end tests), not yet on a card.
